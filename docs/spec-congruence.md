# 단원 1 · 합동 (Congruence) — 세부 스펙

> 📍 상태: **확정**
> 🔀 브랜치: `feature/congruence-unit`
> 🎯 목표: 초5가 "포개어 보면 완전히 겹친다"를 직접 손으로 확인하며 learns

---

## 1. 학습 목표

합동의 정의(모양·크기가 같아 포개면 완전히 겹침)를 **경험으로 이해**한다.

### 합동의 3요소

| 조건 | 내용 | 아이가 흔히 틀리는 것 |
|---|---|---|
| **① 모양** | 대응하는 변의 길이·각이 같다 | 모양만 보고 "합동이다" |
| **② 크기** | 전체 크기가 같다 | 크기 달라도 "합동"이라 착각 |
| **③ 방향** | **달라도 된다** ⚠️ | 방향 다르니 다르다고 착각 |

> ⚠️ **③ 방향은 상관없다**가 이 앱이 가장 잘 가르칠 수 있는 부분입니다.
> 교과서로는 납득이 어렵지만, **직접 돌려서 겹치면 한 번에 이해**합니다.

---

## 2. 연습 시뮬레이션 — 4개 모드 (난이도 순)

### 모드 1. 포개기 연습
두 도형을 겹쳐보고 "같은 모양이야"를 발견한다.

- 기준 도형 위에 다른 도형을 **드래그로 포개기**
- 겹치는 순간 **실시간 판정 표시**
  - `모양·크기 모두 같음 → "같은 모양이야!" ✅`
  - `모양만 같음 → "모양은 같은데 크기가 달라!" ⚠️`
  - `안 겹침 → 힌트 버튼 활성화`
- **포개는 행위 자체가 학습**입니다. 정답 버튼이 없음.

### 모드 2. 변·각 관찰
초5 "합동 조건" 수업에 해당.

- 도형을 겹친 뒤 **변의 길이 / 각을 눈으로 비교**하게 함
- 각 변에 `ㄱ, ㄴ, ㄷ…` 라벨, 길이는 시각적으로(눈금) 표현
- 아이가 직접 **"같다 / 다르다"** 를 눌러 확인
- 앱이 답을 알려주기보다 **비교 대상만 나란히 보여줌**

### 모드 3. 다시 그리기
기준 도형을 보고 반대편에 같은 모양을 직접 그린다.

- 기준 도형이 **반투명**으로 한쪽에 표시
- 아이가 **손가락으로 직접 그리기**
- 판정: 정점 허용 오차 **화면의 2%** (다시 그리기이므로 더 관대하게)
  - 접두선/베지어 보정 후 비교

### 모드 4. 더 찾아보기
여러 도형 amongst 합동인 것만 찾는다. (경량 퀴즈)

- 5~8개 도형이 한 화면에
- 합동인 것만 **드래그해서 따로 모아두기**
- 놓을 때마다 즉시 판정

## 3. 문제 — 4개 유형 (총 5~7문항)

### 유형 A. 합동인 도형 고르기 ✅
> "다음 중 A와 합동인 도형을 **모두** 고르세요."

- 선택지 4개 중 정답 **다수 가능**
- 정답/오답 **모두** 표시 (왜 틀렸는지도)

### 유형 B. 합동 아닌 이유 ✅
> "B는 A와 왜 합동이 **아닐까요**?"

**🚨 오개념 함정 처리 — 이 앱의 핵심 설계:**

| 보기 | 정답 여부 | 이유 |
|---|---|---|
| 모양이 다르다 | ✅ 정답 | ① 모양 실패 |
| 크기가 다르다 | ✅ 정답 | ② 크기 실패 |
| **방향이 다르다** | ❌ **거짓 보기** | ③ 방향은 상관없음! |

아이가 "방향이 다르다"를 고르면:

> 🎉 **"정말 잘 봤어요! 그런데 방향이 달라도 합동이에요!"**

**오답을 배움의 기회로 전환합니다.** 정답만 알려주고 끝내지 않습니다.

### 유형 C. 조건 시각 확인 ✅ (빈칸 채우기 대체)
> "합동 조건을 확인해 봅시다"

빈칸 채우기 대신 **시각 문제**로 바꿉니다:

| 문항 | 답 |
|---|---|
| 두 도형의 **변의 길이** | 같니 / 다르니 |
| 두 도형의 **각** | 같니 / 다르니 |
| 두 도형의 **방향** | 같니 / 다르니 |
| → 둘 다 "같니"니까? | **합동이다** ✅ |

> 손으로 만지지 않으므로 ❌ → 도형에 👆 터치하면 변·각이 하이라이트됨

### 유형 D. 실전 문제 ✅ (설명형 대체)
> "이 도형들이 왜 합동인지, 직접 포개어 확인해 보세요"

글자를 쓰는 대신 **시뮬레이션 문제**로 변환합니다:
- 도형들을 자유롭게 **포개어 보라고 안내** → 실험 후 "이제 왜 합동인지 아는 tell 있나요?" 선택
- 또는 **"찾아낸 것"** 을 선택하는 형식

## 7. 핵심 기술 — 합동 판정 엔진

### 판정 로직 (모드 1·4의 핵심)

```
1. 위치 정렬    두 도형의 중심을 겹침
2. 회전 정렬    각도 차이만큼 회전 시도 (방향 달라도 됨)
3. 뒤집기 정렬  반사 여부 두 가지를 모두 시도
4. 허용 오차 비교  모든 꼭짓점 쌍의 거리가 ε 이내?
                  → 모양·크기 모두 일치  [합동] ✅
                  → 모양만 일치         [모양은 같고 크기가 다름] ⚠️
                  → 불일치             [합동 아님] ❌
```

### 허용 오차

| 상황 | ε 값 | 이유 |
|---|---|---|
| 포개기 모드 | 화면의 **1.5%** | 관대하게 (아이 손놀림) |
| 다시 그리기 | 화면의 **2%** | 손으로 그리므로 더 관대하게 |

> ✅ **검증 완료**: 180° 회전 시 꼭짓점별 오차는 ε × 정점수로 선형 증가하며,
> 정점 3개 기준 ε=1.5%일 때 누적 0.0003% 수준입니다.
> **1.5%는 충분히 관대하며, 180° 회전에 대한 별도 완화 규칙은 불필요합니다.**
